# 问题汇总（问题 → 措施 → 来源）

> **用途**：把「踩过的坑 / 定过的口径」集中在**一张可检索的表**里，省得每次去翻 `DEEPCODE.md` 各节和 memory 里的主题文件。
>
> **来源列必填**（用户 2026-10-16 定）。写法统一为下面几种，便于回查：
> - 文件 + 节：`DEEPCODE.md §工具坑：read_pdf 的页码`
> - memory：`memory\write-truncation-incident-2026-09-19.md`
> - 备案：`备案 2026-10-11（lessons-recent.md）`
> - 用户定口径：`用户 2026-10-10 定`
> - 实测：`实测 2026-10-11`
>
> **写法**：一条一行；**新条目按类别追加到对应分区末尾，不改旧行**。口径被推翻时，**旧行标 ⛔ 并写明「被 X 取代」**，不删（留追溯）。
>
> **与备案的分工**：`memory\lessons-recent.md` 是「一件事一条的流水账」；本文件是「按问题聚类的汇总表」——本文件的「来源」大多回指备案正文。
>
> **维护**：发现新坑 → **先在本文件加一行**，再决定要不要落到 `DEEPCODE.md` / memory 正文。
>
> 🔴 **本文件不在任何 RAG 库 `data_dir` 内 ⇒ 改动后不需要重建索引。**

分区：`① 环境与联网` · `② 工具坑` · `③ 流程与纪律` · `④ 资料与学科` · `⑤ 未解决 / 待观察` · `⑥ 已固化`

**状态标记**（写在 # 列之后）：`⏳` 未解决 ｜ `✅` 已固化（措施已进 `DEEPCODE.md` 某节 或 某脚本 / recipe）｜ `⛔` 已作废（被 X 取代）。**同一问题第 2 次复发 → 在来源列标 `×2`，并升级成 DEEPCODE 硬规则**（一次偶发只记账，防规则膨胀）。
